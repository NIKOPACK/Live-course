# 概要设计

由 [02-product-manual.md](02-product-manual.md) 推出产品形状。不在这里发明手册没有的能力。

## 定位

LiveCourse 是自主学习里的一位 Agent 老师：备课、讲授、回应插话、检查，把一堂课教完。材料为上课服务。生成完不是结束；改课也不是产品。课程之间对知识内容保持隔离，但平台会逐步形成对学习者本人「怎样学得更好」的受限认识。

## 三层

```
呈现层    舞台 + 一位教师（Airi + 全双工）+ 学习者插话
控制层    教案 · 动作日志 · 证据 · 多层记忆 · 课堂控制器 · 台上教师
材料层    DSL · 生成 · 存储（编辑器与导出不进产品面）
```

- **材料层**：继续用现有生成与存储，给课堂上材料。编辑器、Agent 改课工具、PPTX / MP4 导出不出现在学习者界面；S0–S2 不重写这些代码，只从入口撤下。
- **呈现层**：课堂主通道是课堂控制器 + Realtime 教师 + 舞台。圆桌从默认路径撤下。课堂页没有编辑态。
- **控制层**：先让「一位老师把已有材料教完」成立，再补独立教学设计、学情摘要、检查驱动下一步与有作用域的记忆。学情与记忆只给台上 Agent 用，不增加学习者工作台。

拿掉控制层，课堂退回「能播的生成课」。拿掉材料层，教师没有可教的东西。两层都留，互相不替代。

## 记忆作用域

记忆不是一个全局自由文本池，而是三种不同作用域、生命周期与 schema 的数据：

| 层 | 作用域 | 可以包含 | 绝不越界 |
|---|---|---|---|
| 当前课堂工作记忆 | `classroomSessionId` | 当前节点、最近插话、`resumeNode`、当前题状态、临时教学调整和短摘要 | 不无界累积；未归档的临时内容不成为长期画像 |
| 同课程学习记忆 | `learnerId + courseId` | 该课程知识内容、教案引用、进度、作答证据、误解、未解决问题与该课有效的教学调整 | 不被另一课程读取或注入；学习程度只在此课程 / 主题内成立 |
| 跨课程学习者记忆 | `learnerId` | 语言、教学方法、节奏、互动 / 反馈方式、无障碍需要与稳定约束等 learner-only 属性，带来源、置信度和更新时间 | 禁止课程名、知识点、题答、分数、掌握结论、课程摘要和原始对话 |

同课重开读取「同课程学习记忆 + 跨课程学习者记忆」；不同课新开只读取跨课程学习者记忆。跨课程学习者记忆回答「怎样教这位学习者」，不回答「这位学习者学过什么」。

单向受控数据流：

```
课堂事件 / 作答
  → 当前课堂工作记忆（session，短期）
  → 归档为同课程证据与摘要（learner + course）
  → 模型只提出 learner-only 画像 candidate
  → 确定性白名单 policy 校验字段、来源、置信度与更新时间
  → 跨课程学习者记忆（learner）
  → 新课只注入白名单画像，不注入来源课程知识
```

一次行为不能生成永久标签；推断需要足够证据，冲突时降置信度或等待再次确认。教师上下文的优先级固定为：**本次明确表达 > 当前课堂状态 > 同课程历史 > 跨课程学习者记忆 > 默认值**。低优先级不得覆盖高优先级，模型无权选择或提升数据作用域。首页草稿与课前回答在生成开始时只进入当前课程；当前明确表达立即影响本课，但只有 session finalization 时，明确为长期 / 通常偏好或跨多课证据达到 policy 门槛的 learner-only candidate 才可写入跨课程学习者记忆。

“跨课程”是同一学习者不同 `courseId` 之间复用 learner-only 画像的语义，不等于跨设备同步。它可以只发生在本机 IndexedDB 或同一已配置存储中；本期不增加账号关联、设备合并、同步冲突处理或跨设备档案。

## 交互原则

[01-user-journeys.md](01-user-journeys.md) 的六列契约是主通道状态机的产品边界。每一步必须同时具备：明确的用户输入方式、系统可见反馈、允许时的跳过或失败恢复、唯一完成条件、完成后的状态迁移，以及 W / C / L 读写声明。

- **显式动作**：创建课程、进入课堂、提交答案、暂停 / 继续、课中重听、未完成时「暂时离开课堂」、首页同课选择「继续 / 再听」、课后再听 / 结束重听与离开，不依赖关闭 / 返回等隐式触发。「继续」只为未完成教学读取 `C + L` 并新建 teaching `W`；首页与课后的「再听」共用独立 replay 生命周期，每次新建 replay `W`、只播放 `C` 中持久化的已讲范围，结束后销毁它并回各自选择态，绝不借 replay finalize、写 `C / L`、产 evidence 或重判掌握。课前确认结束后自动进入预览，以及最后必需动作后自动进入 `finalizing`，是状态机明定的自动迁移；预览就绪后仍须显式进入课堂。
- **反馈闭环**：加载、上传、生成、识别、判分、保存都显示进行中 / 成功 / 失败；失败留在原状态并可恢复，不清空已经成功的兄弟项。
- **状态不冒充证据**：UI 到达某页、播放游标到达节点、音频加载完成、重听、重试或跳过都不是学习证据。实际讲授完成只驱动课程讲授进度；只有幂等提交的检查结果产生 evidence 并投影 `GoalState`。两者共同决定必需动作是否已补齐，但不能互相冒充。
- **作用域可见行为一致**：新课只使用 L；同课恢复使用 C + L 并新建 W；设置和普通 UI 草稿不属于学习记忆。界面不能通过恢复或重试绕过这一边界。

## 主通道

学习者只接触一条通道：

1. 首页提交需求（可选资料）；系统读取允许的学习者记忆并只追问缺失且会改变本课设计的信息
2. 生成流水线产出场景与动作
3. 播放引擎按动作上课
4. 全双工教师开口、调用板书 / 高亮 / 导航
5. 插话与检查写入同一条动作日志；证据投影目标状态并按作用域归档，只进教师上下文

PBL 与扮演任务只是材料 / 场景类型，不是首页上的第二条产品，也不启用第二个发言者。所有角色、项目情境与对话材料都由同一位教师通过舞台和类型化动作呈现；若未来确需第二位台前 Agent，必须先在 `01` / `02` 写明交互与失败恢复。

## 明确不做

手册「不可以」的条目，设计上视为不存在：人类教师、改课、同学圆桌、三种生成模式、多课时规划、摄像头、BKT / FSRS、跨设备档案。也不做无作用域的自由文本 memory blob、跨课程知识档案，或把其他课程的题答 / 掌握结论召回新课。README 不得把未做项写成当前能力。

## HTML 课堂材料

新课材料采用模型原生 HTML：主 Agent 在逐页生成前决定全课视觉方向，节点生成共享该方向但不受固定元素、版式或 widget 类型约束。HTML/CSS、SVG、Canvas 和沙箱内 JavaScript 用于教学表现；检查仍保留结构化题目及原有显式提交、判分和证据边界。材料运行不能直接修改宿主页、课程进度或记忆。旧课继续读取原格式，不做破坏性迁移。

## 完成标准

能指出主通道五步，能用六列契约解释每步输入、反馈、恢复、迁移与 W / C / L，能解释三种记忆作用域与上下文优先级，并能说明编辑器为什么还在仓库里（待撤产品面，不是学习者功能）。不能从本文推出教师产品、第二条生成线、跨设备同步或跨课程知识共享。
